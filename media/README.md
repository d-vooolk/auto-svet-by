# Папка для фотографий

Складывайте снимки сюда как есть — сжимать, обрезать и переименовывать
заранее не нужно.

Структуру придумывайте любую, лишь бы вам было удобно искать. Например:

```
media/
  categories/
    lamps.jpg
    lenses.jpg
  lamps/
    osram-nb200/
      main-1.jpg      общие фото товара
      h7-1.jpg        фото варианта с цоколем H7
      h7-2.jpg
      hb4-1.jpg
  lenses/
    aozoom-a5/
      main-1.jpg
```

В JSON пишется путь **относительно этой папки**:

| Файл на диске | Путь в JSON |
|---|---|
| `media/lamps/osram-nb200/h7-1.jpg` | `"lamps/osram-nb200/h7-1.jpg"` |
| `media/categories/lamps.jpg` | `"categories/lamps.jpg"` |

## Что происходит при сборке

`npm run build` запускает `scripts/images.mjs`, который из каждого снимка
делает:

- версии в **AVIF** и **WebP** на ширины 400, 800, 1200 и 1600 пикселей;
- один JPEG на случай очень старого браузера;
- крошечную размытую заглушку — она показывается, пока грузится фото, и
  избавляет от скачка вёрстки.

Результат уходит в `public/img/`. Эта папка в `.gitignore` — она целиком
пересобирается из `media/`, держать её в репозитории нет смысла.

Повторная сборка обрабатывает только изменившиеся файлы, так что второй и
последующие разы проходят быстро. Пересобрать всё принудительно:

```
npm run images:force
```

## Требования к снимкам

- **Формат:** JPG, PNG, WebP или AVIF.
- **Размер:** чем больше исходник, тем лучше — от 1600 px по длинной стороне.
  Мелкие фото не растягиваются: если исходник 900 px, версии на 1200 и 1600
  просто не создаются.
- **Фон:** лучше белый или светло-серый. На карточках фото лежит на светлой
  подложке, тёмный фон будет выделяться прямоугольником.
- **Поворот:** фото с телефона можно кидать как есть, EXIF-поворот
  учитывается.

## Если фото ещё нет

Ничего страшного. Товар без фотографий собирается и работает — на месте
снимка появляется аккуратная заглушка с иконкой фары. При сборке в консоль
выведется список недостающих файлов, чтобы было видно, что осталось
доснять.
